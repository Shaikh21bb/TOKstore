# ТОК — магазин смартфонов и аксессуаров

Цены в тенге (₸). Демо-доставка: самовывоз — бесплатно, курьер — 2 000 ₸.

MVP: 8 демонстрационных смартфонов Apple iPhone, Samsung Galaxy, Xiaomi и Google Pixel и 12 аксессуаров. Каталог хранится в Cloudflare D1, а корзина, избранное и демо-заказы — в браузере.

## Сайт

- Основная версия с каталогом D1 и админ-панелью: https://tok-accessories-mvp.peppyzebra64.chatgpt.site
- Статическая витрина GitHub Pages: https://shaikh21bb.github.io/TOKstore/

GitHub Pages автоматически публикуется из ветки `main`. На нём доступны каталог из `db/seed.json`, поиск, фильтры, корзина и демонстрационное оформление. Управление товарами работает только в основной версии, потому что GitHub Pages не запускает сервер и базу D1.

Основная версия также включает цифровую карту клиента, QR-коды товаров, мобильный POS `/pos` и аналитику владельца `/dashboard`. Эти модули используют D1 и работают только на серверной публикации. PIN продавца по умолчанию `1234` предназначен для демонстрации; перед реальной эксплуатацией задайте секретный `STAFF_PIN` в окружении Sites.

## Админ-панель

Открыть `/admin` под аккаунтом владельца магазина. Пароль для админки не нужен: доступ через вход ChatGPT. Сервер проверяет владельца на каждой операции; права задаёт runtime-переменная `ADMIN_EMAIL` в Sites.

Можно добавить, редактировать, скрыть и удалить товар. Поля: название, бренд, категория, модель, цвет/память, цены, остаток, порядок сортировки, описание, характеристики и подпись карточки. Для фото можно выбрать иллюстрацию, вставить HTTPS-ссылку или загрузить PNG/JPEG/WebP до 600 КБ. Загрузки хранятся с товаром в D1, что подходит для небольшого MVP.

Удаление требует подтверждения. Изменение уже отредактированной карточки не перезаписывает чужую правку: сервер сообщает о конфликте версий. Скрытые товары доступны в админке, на витрине их нет. Товар с нулевым остатком виден, но не добавляется в корзину.

## Каталог

Поиск, категории, бренд, модель, сортировка, карточка с характеристиками. При загрузке, возвращении в вкладку и оформлении корзина сверяется с каталогом: удалённые/скрытые товары убираются, количество ограничивается наличием, цены обновляются.

Начальный ассортимент из `db/seed.json` загружается в D1 один раз через идемпотентную транзакцию. После удаления товаров они не восстанавливаются из образцов. Последующие публикации сохраняют базу и правки.

## Локальная разработка

```sh
npm ci
npm run db:generate # только после изменения db/schema.ts
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_peaceful_korvac.sql
npm run dev
```

Открыть http://localhost:4173. В незакоммиченном `.dev.vars` для локального теста указать `ADMIN_EMAIL=seedy@sites.test`, затем перейти на `/signin-with-chatgpt?return_to=/admin` для тестового входа. Этот вход существует только при локальной разработке. На опубликованном сайте авторизацию обеспечивает Sites, локальное значение не публикуется.

Проверить статическую витрину перед публикацией:

```sh
npm run pages:build
npx serve .pages-dist
```

Не применять уже применённую SQL-миграцию повторно. Новые миграции добавлять, не переписывая старые. Источники витрины: `web/index.html`, `public/app.js`, `public/style.css`. Админка: `web/admin.html`, `public/admin.js`, `public/admin.css`. Сервер: `server/catalog.ts`; схема и образцы — `db`.

## Перед реальными продажами

Добавить реальные товары, цены, фото, контакты и реквизиты. Подключить серверные заказы, оплату, доставку, юридические документы и публичный доступ. Оформление пока демонстрационное: заказ не отправляется продавцу, оплата не производится и склад не резервируется. Тестовые имя/телефон/адрес не сохраняются в истории.
